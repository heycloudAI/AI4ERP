AI4ERP · Oracle ERP Cloud AI Architecture

La boucle Agent AI4ERP

Toute plateforme Agent AI de production suit une boucle en six étapes. Les composants ci-dessous s’insèrent dans cette boucle. Pour AI4ERP, l’objectif est de connecter un agent intelligent à Oracle ERP Cloud, OIC, Jira et aux connaissances projet, tout en gardant sécurité, audit et validation humaine.

La boucle

Six étapes. La sortie d’une étape devient l’entrée de la suivante. Le cycle se répète à chaque interaction - c’est pourquoi la mémoire est à la fois le point de départ et le point d’arrivée.

01 · INPUT
Utilisateur / Trigger
Un prompt, un webhook, une exécution planifiée, un email entrant ou un ticket Jira. Quelque chose déclenche un tour.
02 · LOAD
Memory + RAG
Charger le contexte pertinent avant que le LLM ne raisonne. Memory = ce qui est connu de l’utilisateur ou du projet. RAG = ce qui se trouve dans le corpus documentaire.
03 · REASON
LLM
Le modèle utilise le contexte chargé et décide : répondre directement, appeler un tool, ou planifier une séquence multi-étapes.
04 · FILTER
Tools + Rails + Guardrails
L’intention du modèle est contrôlée. Les rails appliquent les règles métier. Les guardrails bloquent les usages non sûrs. Les tools sont les capacités réellement connectées.
05 · ACT
Action / Execution
Quelque chose se produit réellement : appel API Fusion/OIC/Jira, écriture, message envoyé, fichier généré ou réponse streamée à l’utilisateur.
06 · LEARN
Audit + Eval + Feedback
Tracer tout le tour, évaluer la qualité, journaliser pour audit/compliance et réinjecter les apprentissages utiles dans la mémoire.

Les composants clés

Regroupés par rôle. Chaque composant de notre plateforme Agent AI de production s’insère dans l’un de ces groupes.

GROUP 01 · STAGE 03
Reasoning Core
La couche de raisonnement. Génère, vectorise et route vers le bon modèle.
LLM claude · gpt · gemini
Le générateur. Il prend le contexte et retourne une réponse ou un tool call.
Embeddings vectors
Transforme le texte en vecteurs numériques. Alimente le RAG et la recherche sémantique.
Model routing / gateway cf ai gateway
Choisit le modèle adapté selon la tâche. Gère fallback, cache, coût et rate limits entre providers.
GROUP 02 · STAGE 02
Knowledge & State
Ce que le modèle connaît avant de générer. Corpus + memory + storage.
RAG vectorize
Récupère l’information depuis un corpus contrôlé : docs Oracle, specs, schémas, procédures, tickets Jira, emails projet.
Memory short + long term
Différent du RAG. Short-term = la conversation en cours. Long-term = contexte utilisateur/projet conservé entre sessions.
Storage d1 · r2 · kv
État durable pour le reste : base structurée, stockage de fichiers, configuration rapide.
GROUP 03 · STAGE 04 → 05
Capability
Ce que le modèle peut faire au-delà de parler : tools, sandbox, multimodal.
Tool use / function calling mcp · native
Le pattern général. MCP est un mode de transport ; le function calling natif en est un autre. Les deux peuvent coexister.
Sandbox / execution env iox
Code interpreter, automation ou computer use. L’espace où l’agent peut travailler sans toucher directement la production.
Multimodal layer stt · tts · vision
Voix entrante/sortante, vision, image generation. Dans AI4ERP : module speech type ElevenLabs et interactions vocales.
GROUP 04 · STAGE 04
Control
La couche sécurité + policy. Ce que l’agent a le droit ou non de faire.
Rails / rules policy
La policy métier : qui peut faire quoi, quand, avec quelles contraintes.
Guardrails i/o filter
Distinct des rails. Filtrage input/output : PII, prompt injection, jailbreak, contenu non conforme.
Identity, auth, RBAC, tenancy authjs
Qui est l’utilisateur, quelles BU/ledgers/données il peut voir, et ce que son agent peut faire en son nom. Point critique en B2B/ERP.
Human-in-the-loop / approval gates hitl
Quand l’agent doit s’arrêter et demander une validation humaine avant une action sensible ou irréversible.
GROUP 05 · WHOLE LOOP
Orchestration
Le harnais autour de la boucle : durabilité, async, erreurs, streaming.
Agent loop / planner harness
Le wrapper autour du LLM qui décide la prochaine étape, déclenche les tools, gère les erreurs et maintient le scratchpad.
Workflows / durable execution cf workflows
Pour les tâches longues : ESS jobs, traitements OIC, rapprochements, suivis batch, reprise après erreur.
Queues / async cf queues
Ingestion webhook, batch processing, retry, découplage des traitements longs.
Streaming layer sse · ws
UX temps réel : token streaming, réponses partielles, annulation, événements de progression.
GROUP 06 · STAGE 06
Operations
Savoir si ça fonctionne : eval, trace, audit, coût.
Evals offline + online
Tests de non-régression sur jeux de référence + scoring LLM-as-judge sur trafic réel.
Observability / tracing braintrust · langsmith
Chaque prompt, chaque tool call, chaque coût. Traces de bout en bout rejouables.
Audit log soc2 · gdpr · ai act
Séparé de l’observability. Journal immuable pour audit, GDPR, AI Act, SOX-like controls.
Caching prompt · semantic
Prompt cache + cache sémantique. Levier important de performance et de coût.
Cost / metering / rate limits tokens
Suivi tokens par user/tenant, plafonds, throttling. Indispensable pour contrôler les coûts.
GROUP 07 · STAGE 01 + 05
Surface
Ce que l’utilisateur voit et comment il corrige ou valide.
UI / chat / action surface next.js · shadcn
Frontend, citations, confirmations d’action, streaming, visualisation des tool calls.
Feedback loop thumbs · corrections
Feedback utilisateur, corrections structurées, données réinjectées dans evals et memory.
GROUP 08 · FEEDS STAGE 02
Data Ingestion
Le pipeline qui alimente le RAG. Sans lui, le modèle est aveugle.
Document pipeline parse · chunk · embed
Parser PDF/HTML/transcripts, chunker, embedder, indexer, versionner et rafraîchir les contenus.
RACCOURCI MENTAL

Toute plateforme Agent AI enterprise suit la même boucle

À retenir pour cadrer rapidement l'architecture AI4ERP :

(memory + RAG) → LLM → (tools + rails + guardrails) → action → (audit + eval + feedback) → memory

Chaque composant ci-dessus s’insère dans cette boucle. S’il manque une étape, il y a un risque d’architecture. Si deux composants font le même travail, il y a duplication.
